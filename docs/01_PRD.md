# Memoir AI - 제품 요구사항 정의서 (PRD)

## 1. 개요 (Overview)

### 1.1 제품 비전 및 목적
*   **서비스명**: Memoir AI (지능형 인지 장부)
*   **비전**: 매일 소비되는 휘발성 정보를 사용자의 주관적 맥락과 결합하여, 시간이 흐를수록 가치가 높아지는 **'개인화된 지식 온톨로지'** 구축.
*   **슬로건**: "단순 기록(Record)이 아닌, 자산(Asset)으로의 전환"
*   **목적**: 정보 과부하 시대에 사용자가 접하는 파편화된 정보를 단순 저장하는 것을 넘어, AI와의 상호작용을 통해 사용자의 생각과 맥락을 더해 '살아있는 지식'으로 자산화함.

### 1.2 배경 및 필요성
현대 지식 노동자와 학습자들은 웹서핑, 업무 메신저, PDF 등 다양한 경로로 정보를 접하지만, 대부분은 **'읽고 잊혀지는(Read & Forget)'** 휘발성 정보로 남습니다. 기존의 노트 앱(Notion, Obsidian 등)은 정리를 위해 사용자가 많은 에너지를 투입해야 하는 부담이 있어, 결국 '디지털 쓰레기통'이 되기 쉽습니다. Memoir AI는 AI 에이전트를 통해 정리의 부담을 덜고, 정보 간의 연결성을 자동으로 발견하여 지식의 활용도를 극대화합니다.

## 2. 타겟 사용자 (Target Persona)

### 2.1 메인 페르소나: "인사이트 헌터" (지식 노동자)
*   **특징**: 매일 쏟아지는 업계 뉴스, 리포트, 기술 블로그를 소비함.
*   **Pain Point**: 
    *   "좋은 글을 봤는데 나중에 찾으려니 어디 있는지 모르겠다."
    *   "저장은 많이 해뒀는데 다시 보지 않는다."
    *   "이 정보가 내 업무에 어떻게 연결되는지 정리가 안 된다."
*   **Needs**: 최소한의 노력으로 정보를 저장하고, 필요할 때 문맥에 맞게 다시 발견되기를 원함.

### 2.2 서브 페르소나: "성장하는 학습자"
*   **특징**: 자기 계발에 관심이 많고, 학습한 내용을 내 것으로 만들고 싶어함.
*   **Needs**: 단순히 베껴 적는 것이 아니라, 질문을 통해 사고를 확장하고 지식을 구조화하고 싶어함.

## 3. 사용자 여정 (User Journey)

| 단계 | 행동 패턴 (User Action) | 시스템 반응 (System Action) | 감정/가치 |
| :-- | :-- | :-- | :-- |
| **1. Ingest (낮)** | 웹서핑, 메신저, PDF 등 파편화된 정보(URL, 텍스트)를 공유/복사하여 서비스에 '던지기'만 함. | **[Multi-modal Scout]** 광고, 배너 등 노이즈를 제거하고 본문 핵심 내용만 깔끔하게 추출하여 임시 보관함(Inbox)에 저장. | "귀찮은 정리 없이 일단 던져두면 되니 편하다." (안심) |
| **2. Evening Ritual (밤)** | 하루를 마무리하며 샤워 후 앱을 켬. | AI가 오늘 수집된 지식 조각들을 보여주며 대화를 시작함. | "오늘 내가 이런 정보들에 관심을 가졌구나." (회고) |
| **3. Refining (상호작용)** | AI의 질문("이 내용이 현재 진행 중인 프로젝트 A와 어떤 관련이 있나요?")에 답하며 생각을 구체화. | **[Socrates Agent]** 사용자의 답변을 바탕으로 원문을 요약/수정하고, 사용자의 코멘트(Insight)를 메타데이터로 추가. | "읽기만 했을 때보다 훨씬 명확해졌다." (사고 확장) |
| **4. Connecting (자동)** | 사용자가 잠든 사이 혹은 대화 직후. | **[Architect Agent]** 정제된 지식을 기존 지식 그래프(Knowledge Graph)에 연결. 관련된 과거 메모와 자동 링크 생성. | "내 지식이 연결되고 쌓이고 있다." (자산화) |
| **5. Capitalization (활용)** | 새로운 아이디어가 필요하거나 글을 쓸 때. | **[Semantic Search]** 키워드가 생각나지 않아도 문맥으로 검색 시, 과거의 관련 지식과 현재의 연결 고리를 시각적으로 제시. | "예전에 고민했던 게 지금 도움이 되네!" (효용감) |

## 4. 핵심 기능 요구사항 (Functional Requirements)

### 4.1 Multi-modal Scout (수집 에이전트)
*   **기능 정의**: URL, PDF, 이미지(OCR), 텍스트 등 다양한 소스에서 노이즈 없는 순수 본문 및 메타데이터 추출.
*   **세부 사항**:
    *   `Readability Engine`: 웹 페이지의 광고, 내비게이션 바, 팝업 등을 제거하고 기사 본문만 추출.
    *   `Auto-Tagging`: 1차적으로 카테고리, 주제, 키워드 자동 태깅.
    *   `Source Tracking`: 원본 출처(URL) 및 수집 시점 자동 기록.

### 4.2 Socratic Dialogue (정제 에이전트)
*   **기능 정의**: 사용자가 수동적으로 정보를 소비하는 것을 방지하기 위해 질문을 던지는 대화형 인터페이스.
*   **세부 사항**:
    *   `Insight Prompting`: "이 글의 핵심 주장은 무엇이라고 생각하시나요?", "이전에 저장한 [글 B]와 상반된 의견 같은데 어떻게 생각하세요?" 등의 질문 생성.
    *   `Interactive Summary`: 대화를 통해 사용자가 구술한 내용을 바탕으로 요약문 재작성.

### 4.3 Auto-Ontology Mapping (구조화 에이전트)
*   **기능 정의**: 텍스트 내 엔티티(Entity)를 식별하고 지식 그래프 형태로 관계 설정.
*   **세부 사항**:
    *   `Entity Extraction`: 인물, 회사, 기술, 프로젝트, 경험 등 고유 명사 및 개념 추출.
    *   `Relation Extraction`: A와 B의 관계(is-a, part-of, related-to, worked-on) 추론.
    *   `Graph Builder`: RDF(Resource Description Framework) 혹은 Property Graph 형태로 데이터 저장.

### 4.4 Semantic Search & Linking (활용 및 검색)
*   **기능 정의**: 단순 키워 매칭이 아닌 의미(Vector) 기반 검색 및 연관 지식 추천.
*   **세부 사항**:
    *   `Context Awareness`: "저번 달에 고민했던 마케팅 전략 관련 글 찾아줘"와 같은 자연어 질의 처리.
    *   `Serendipity Linking`: 사용자가 문서를 작성할 때, "이와 관련된 과거의 메모가 있습니다"라고 사이드바에 추천(Backlink).

## 5. 기술 아키텍처 및 데이터 전략 (Technical Strategy)

*   **LLM Pipeline**
    *   **Parsing Model**: 작은 모델(Cheap)로 HTML/PDF 처리.
    *   **Thinking Model**: 고성능 모델(Expensive)로 소크라테스 대화 및 논리적 연결 추론.
    *   **Embedding Model**: 벡터 검색을 위한 텍스트 임베딩 생성 (e.g., OpenAI v3, Cohere).
*   **Database**
    *   `Vector DB`: 텍스트 임베딩 저장 (Semantic Search 용).
    *   `Graph DB` (옵션): 지식 관계 저장 (Neo4j 또는 간소화된 관계형 테이블).
*   **Privacy First**
    *   사용자의 사적인 생각이 담기므로, 데이터 암호화 및 로컬 우선 저장(Local-First) 고려 가능.

## 6. 성공 지표 (Success Metrics)

*   **Retention**: Evening Ritual(밤 9-11시) 시간대 앱 실행률 및 리텐션.
*   **Interaction Rate**: 수집된 글 대비 소크라테스 대화가 진행된 비율 (단순 저장이 아닌 '소화'된 비율).
*   **Graph Growth**: 사용자당 생성된 노드(Node)와 엣지(Edge, 연결선)의 수 증가 추이.

## 7. 로드맵 (Roadmap)

### Phase 1: MVP (Minimum Viable Product)
*   핵심 기능: URL 링크 파싱, 기본 질문 생성, 텍스트 저장, 단순 검색.
*   목표: "일단 던져두고, 밤에 대화하며 정리한다"는 핵심 루틴 검증.

### Phase 2: Knowledge Graph
*   핵심 기능: 엔티티 자동 추출, 지식 그래프 시각화, 연관 메모 추천 알고리즘 고도화.
*   목표: 정보의 연결 경험 제공.

### Phase 3: Extension
*   핵심 기능: 브라우저 익스텐션, 슬랙 봇 연동, 이미지/음성 입력 지원, PDF 주석 기능.
*   목표: 수집 채널 다각화.
